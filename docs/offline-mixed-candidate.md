# Preparing mixed Intel and NVIDIA collateral

Start with a signed Intel-only candidate for the target and the [B200 experiment](../test/e2e/b200/README.md) on the assigned GPUs. The trusted site directory holds `site-time`, `enrolled-quote.bin`, `profile.json` and the independently provisioned `nvidia-roots.pem`. Obtain the approved enrollment digest and the digest of the original successful refresh report from the independent qualifier over an authenticated channel. Keep the received capture and site inputs read-only.

In the qualification approval use the operator-assigned provisioning inventory ID from the independently installed `trusted-site/profile.json` field `target`. Use this string in Intel preparation and the GPU approval. Include a `rimResponses` object mapping each expected **vendor RIM ID** to the lowercase SHA-256 of the exact RIM service response. The values must match the `rimSha256` list. Record these before running the challenge. The SDK checks the returned ID, decodes the signed RIM in the response and checks its signatures. [Pinned SDK RIM handling](https://github.com/NVIDIA/attestation-sdk/blob/0c1be386a8fbb8f2766a6a556d10df86f5fed9d3/nv-attestation-sdk-cpp/src/rim.cpp#L501-L533)

Keep the successful checker stdout as `gpu/refresh-report.json`. Verify both its digest and the two refresh timestamps independently with the qualifier. Copy the complete `b200-run/` directory to `gpu/run/`, including its approval, policy.rego, challenge, verified UEIDs, attest.json, inventory.csv and nvattest.sha256, and copy the original RIM responses to `gpu/rims/<response-sha256>`. Put the enrolled per-certificate inputs in `gpu/responses/<name>/{cert.pem,issuer.pem,ocsp.der}`, intermediates in `gpu/intermediates.pem`, and only the logs from the same run’s private responders in `gpu/served-rim.sha256` and `gpu/served-ocsp.sha256`. Install Bash, Python 3.11+, jq, OpenSSL 3 and chronyd, and set `B200_NTS_SERVER` and `B200_NTS_CA` for the independent site clock. The preparer reruns the qualification checker and its NTS preflight. Supply the original authenticated UTC Unix timestamps, starting before connected vendor collection and ending after the checked responses arrive and are imported at the disconnected site. Install the reviewed Intel media CLI build that supplies `c8s collateral check-intel RAW-QUOTE PROFILE MANIFEST SIGNATURE OBJECT-DIRECTORY` on the trusted PATH. Record its source revision and executable digest in the site inventory. This command depends on that CLI and the B200 qualification scripts in this checkout.

```sh
scripts/airgap/prepare-mixed intel-media trusted-site gpu "$APPROVAL_SHA256" \
  "$QUALIFICATION_SHA256" "$REFRESH_STARTED_UNIX" "$IMPORT_FINISHED_UNIX" \
  "$MIXED_GENERATION" "$MEDIA_SIGNING_KEY" mixed-candidate
```

Reserve an unused generation greater than `jq -r .generation intel-media/active` in the site’s signer inventory. Mount all incoming bytes read-only throughout preparation. Both the mixed manifest and its on-media selection name the reserved generation. The workstation rechecks the signed Intel objects against the enrolled quote and verifies the observed GPU claims, exact OCSP responses, approved maximum age, responder coverage and the measured media window. The current site clock must agree with the NTS-checked workstation and leave more than one complete measured trip plus two seconds for clock uncertainty before expiry. The preparer preserves Intel response headers and original NVIDIA response bytes. The manifest expires at the earliest Intel, OCSP or GPU certificate-chain deadline. Its Ed25519 signature covers the target, generation, expiry and every selector and content hash. `mixed-candidate/active` describes the candidate on media. A failed preparation never publishes a site selection. The completed directory is published in one rename on the staging filesystem.

The production Intel importer rejects a mixed manifest. Site activation requires a qualified local NVIDIA verifier capable of checking the selected generation's RIMs and OCSP records for each assigned device at current authenticated site time. On each challenge it must authenticate the current selection, resolve `nvidia/rim/<ID>` and `nvidia/ocsp/<fingerprint>` from that manifest, reapply the approved cached-status policy and reject a superseded generation. The B200 experiment observes the set of collateral used across the eight devices. Its aggregate SDK report and resolver logs cannot establish which response authenticated each device on a subsequent boot. Independent revalidation also requires the approved target, eight device identities, cached-status policy and maximum age, trusted roots, original verifier capture and authenticated site time. Keep the signed candidate on staging media until that import path and the measured guest are qualified.

The cross-stack test uses the Intel CLI and its public Intel-signed corpus. Set `C8S_INTEL_CORPUS` to the CLI checkout’s `internal/localverify/testdata/uptodate` directory and run `pytest -q scripts/airgap/test_mixed.py`. The cross-stack case skips when `C8S_INTEL_CORPUS` is unset and fails if a configured corpus or CLI is unavailable. A release reviewer must run it with the corpus and check the pass count. The other case tests synthetic GPU staging. The commands were exercised with Python 3.13 and pytest 9.2.
