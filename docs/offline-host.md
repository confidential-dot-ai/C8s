# Start a disconnected TDX host

Use a dedicated Ubuntu Noble amd64 machine that already boots TDX guests with
eight B200s in CC mode. The owner qualifies the QEMU build, VFIO assignments,
bridge, MAC addresses, GPU BAR layout, QGS transport, and matching TDX firmware
on this host. Start with public egress blocked, site-only DNS, accurate site
time and empty image and package caches. Disable the host image's background
public update services before the pilot.

The released GPU verifier needs public services. The current site importer handles
Intel material only. A qualified NVIDIA verifier release and an importer that
authenticates the combined Intel/NVIDIA snapshot are prerequisites for executing
this installation. Host preparation and fixture checks can proceed earlier.

## Build inputs

Install `scripts/airgap/install.sh` as `site/install.sh` for the verified build.
Add these target-specific files to the approved site inventory.

| File | Contents |
| --- | --- |
| `site/qemu/ta.json`, `site/qemu/worker.json` | JSON arrays with the tested QEMU arguments for memory, CPU count, PCI topology, network and any switches, one string per argument. The installer supplies q35, TDX, KVM, TDVF, Unix QGS, raw guest disk and launch disk. It attaches the worker's encrypted scratch backing disk with serial `confai-scratch`. |
| `site/pck-cache.json` | `{"file":"<qe_id>_<pce_id>"}` using the exact hexadecimal name generated by Intel's PCS client for this platform. Place its opaque cache bytes under `site/pck/<qe_id>_<pce_id>`. |
| `site/k3s-config.yaml` | API bind/advertised address, TLS SAN, cluster CIDR, Service CIDR and cluster DNS matching the approved `worker.yaml`. |
| `site/registry-ca.pem` | CA for the site's TLS registry endpoint. |
| `site/routes.json` | Reviewed route manifest for the sample's workload entry and Service. Omit ACME hostnames from `worker.yaml` for the TA-issued router certificate. |

Set `registry` in `site/target.json` to the private registry's DNS name and
port, `kubeVersion` to the image build's exact kubelet version, and `gpuPCI` to
the eight full lowercase PCI addresses. Each GPU must already be bound to
`vfio-pci` and appear as `host=<PCI address>` in a worker QEMU device argument.
Record the separately attested UEIDs in the qualification. Include the pinned
`docker-registry`, `skopeo`, `tdx-qgs`, QCNL with `local_cache_only`, compatible
QEMU, `python3-yaml`, `openssl`, `ca-certificates`, `curl`, `jq`, `util-linux`,
`genisoimage` and site GPU host tools in the package closure.

On the platform collect its PCK ID CSV with `PCKIDRetrievalTool -f target.csv`.
On the registration machine place that CSV in `platforms/`, run
`pcs-client-tool collect -d platforms` and `pcs-client-tool cache`, then select
the generated cache file for this platform. The host installer copies it into
QGS's local `.dcap-qcnl` cache and restricts QGS to local transports. Verify a
fresh TDX quote after boot. [Intel manual local-cache registration](https://cc-enabling.trustedservices.intel.com/intel-tdx-enabling-guide/02/infrastructure_setup/#on-offline-manual-multi-platform-local-cache-based-indirect-registration)

## Start the services

Provision the dedicated host with its registry leaf certificate and private key
at `/etc/c8s-site/registry.crt` and `registry.key`. Keep the key root-readable
and allow directory traversal for the registry service account. Place the
approved k3s CA material under `/var/lib/rancher/k3s/server/tls` before its
first start. The server's CA must match the worker document. Keep private PKI
material off the archive. [K3s custom CA prerequisites](https://docs.k3s.io/cli/certificate#using-custom-ca-certificates)

Activate the initial snapshot and start the authenticated selection/time service
on the independent site endpoint. Verify the installation archive on a trusted
workstation. Copy its verified payload to `/opt/c8s-offline` on the host and
authenticate the transfer before executing the script. The verified release
binary, chart and operator tools stay at this path for the systemd units.

```sh
sudo /opt/c8s-offline/site/install.sh host
systemctl status qgsd docker-registry c8s-offline-control-plane c8s-offline-ta
```

The installer runs APT and package scripts in a private network namespace.
It starts QGS, seeds the TLS registry by digest, starts agentless k3s, renders
and applies the worker objects, obtains dedicated host-operator credentials,
and starts the TA. Use the independently verified payload on the trusted
workstation for the following commands. `TA` is the replica's host:port and
`KEY` names the operator's private key on that workstation. This Genesis is
for the first launch of a single-replica cluster.

```sh
C8S=./release/c8s-linux-amd64
profile=(--tdx-collateral-profile site/collateral/profile.json)
trust=(--url "https://$TA" --image-policy-file site/ta-pin.json --operator-key "$KEY")
"$C8S" ta verify "https://$TA" --image-policy-file site/ta-pin.json "${profile[@]}"
"$C8S" ta ha decree genesis --config site/ta.yaml --ta-pin site/ta-pin.json \
    --target "$TA" --operator-key "$KEY" --platform tdx --image-manifest site/ta/manifest.json \
    --worker-document site/worker.yaml --worker-image site/worker-image.json \
    --resume-version 0 --alone "${profile[@]}"
"$C8S" allowlist components add release/component-set-tdx.json "${trust[@]}" "${profile[@]}"
"$C8S" allowlist apply site/nginx-entry.json "${trust[@]}" "${profile[@]}"
"$C8S" routes put site/routes.json "${trust[@]}" "${profile[@]}"
```

Start the worker on the host after Genesis and grants. Apply the sample in the
namespace named by the workload entry and route. The following uses `demo`.

```sh
sudo /opt/c8s-offline/site/install.sh worker
sudo /opt/c8s-offline/site/k3s kubectl create namespace demo
sudo /opt/c8s-offline/site/k3s kubectl label namespace demo pod-security.kubernetes.io/enforce=restricted
sudo /opt/c8s-offline/site/k3s kubectl -n demo apply -f /opt/c8s-offline/sample/nginx-confidential-pod.yaml
sudo /opt/c8s-offline/site/k3s kubectl -n demo rollout status deployment/demo-nginx
```

To cold-start just the worker, keep the TA, site endpoint and public-egress
block running. The installer writes a fresh join token and launches another
process against the same measured disk and approved PCI topology.

```sh
sudo systemctl stop c8s-offline-worker
sudo /opt/c8s-offline/site/install.sh worker
sudo journalctl -u c8s-offline-worker -b
```
